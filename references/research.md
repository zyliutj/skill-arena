# 设计依据与边界

核查日期：2026-10-20。

参考 [OpenSkillEval 论文 v2](https://arxiv.org/html/2605.23657v2) 与[官方实现](https://github.com/ALEX-nlp/OpenSkillEval)。研究覆盖演示、前端、海报、可视化和报告任务；不能据此认定其技能排名或评分体系适用于学术研究规划。

采用的思路：固定任务比较 skill；保留无候选 skill 基线；分别检查产物质量与实际 skill 使用；追踪成本与环境。这里优先处理用户真实任务，而非通过反推优秀样本生成基准题。

审视与改进（本项目设计判断，不声称是论文结论）：

- 热度筛选可能漏掉小众优质 skill，因此按适配性、依赖和方法多样性筛选。
- 模型裁判存在文风、位置和同模型偏好，因此匿名、冻结标准、逐维举证，并对近似结果换序复核；这仍不能消除偏差。
- 单次运行不能证明普遍优劣，历史以任务和版本为条件保存，不制造全局总榜。
- 学术规划需要核验研究缺口和实验可行性；表达质量不能弥补虚构引文或数据。
- 严格技能遵循不必然产生更好产物，两者单独记录；必要平台技能造成的共同支撑必须披露。
- 新增候选、依赖更新和实时检索会改变条件，运行时保存快照、来源与时间。

本项目重新编写工作流与脚本，不复制论文数据集或第三方技能正文。官方代码和数据集有不同许可证；未来引入时分别审查。

实现参考：[OpenAI Skills 文档](https://learn.chatgpt.com/docs/build-skills)、[Subagents 文档](https://learn.chatgpt.com/docs/agent-configuration/subagents)。实际执行使用当前工具暴露的能力和限制，不假定某 CLI 参数永久有效。独立上下文与 OS 进程隔离是两种不同能力。
