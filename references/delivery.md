# 远程运行与本地交付

## 开始时决定保存位置

1. 调用 `python scripts/delivery.py detect`，结合当前任务提供的执行主机信息判断 local/remote。SSH 变量是远程证据；没有变量只能得到 unknown，容器或 Linux 本身都不证明远程。已知主机信息时传 `--context local` 或 `--context remote`。不读取、输出 SSH 变量中的地址或凭据。
2. 读取数据根 `delivery-preferences.json`，按客户端标识选择本地根目录。首次未指定时询问一次目标目录，并继续独立工作；已经授权的目录无需重复确认。不要把个人 Windows 路径固化在公共 skill 中。
3. 远程运行时检查是否已有能访问用户电脑的映射目录。仅目录存在不足以证明它位于用户电脑；结合已配置挂载或用户确认的映射验证，再做临时写入/删除探测。可用时将它纳入传输候选；若预计最快，可直接在那里 export 最终报告。计算、中间文件与快照仍留远程。
4. 在可用且已授权的挂载、文件连接器、SSH/SFTP/SCP/rsync 等方式中，自主选择预计端到端耗时最短的方式，先将最终 report.html 传到本地并校验。不得把挂载或 rsync 固定为必然最快。不自动建立新反向 SSH、开放端口、上传公共仓库或使用第三方中转。传输通道不可用则记录 remote-only，交付准确远程路径与阻塞原因；不能声称保存到本地。

配置示例（只存数据根，不提交仓库；客户端键由当前主机上下文确认）：

```json
{"clients":{"my-laptop":{"local_root":"D:/Research","mount_on_remote":null}}}
```

可用 `python scripts/delivery.py configure DATA_ROOT CLIENT_ID ABSOLUTE_LOCAL_ROOT` 保存偏好，已有挂载时加 `--mount VERIFIED_MOUNT_PATH`。保存配置不代表连通性已验证。默认只传最终报告，其他原始文件无论大小均按需下载。不要凭服务器 hostname 推断客户端身份，多电脑偏好分开保存。未知客户端时询问，不随意选第一个。

## 报告优先交付

```sh
python scripts/delivery.py export RUN NEW_BUNDLE
python scripts/delivery.py sync BUNDLE ABSOLUTE_LOCAL_OR_MOUNTED_DESTINATION
```

- export 默认创建 report-only 新版本目录，完整 Markdown/TXT 正文与评估内嵌 report.html，不另传原稿文件；其余文件展示名称、大小和远程位置，提醒用户需要时下载。files 清单默认只有 report.html（少量校验清单与本地回执属于传输控制信息）。仅用户明确要求其他文件或完整包时才传附件；`--full` 包含全部已登记原件，不带缓存、快照或中间文件。
- 本地运行正常报告继续保持单文件模式；只有交付包采用报告优先模式。默认报告可独立阅读，未传原件只给下载提示，不生成失效的本地链接。用户明确要求完整包时才使用包内相对下载链接。
- 只导出 mapping.json 中登记的产物；不用递归复制整个运行目录。运行记录仍保留在执行端。任务需求和引用仍可阅读。
- sync 支持本地或已挂载路径，按 SHA256 跳过相同文件，使用临时文件及原子替换，最后写 delivery-receipt.json。遇到目标已有不同内容时停止，改用新版本目录，防止覆盖用户修改。失败可重试，不删除远程原件。
- 改动后的成果用新交付版本；同一版本可重试并跳过已传文件。用户希望仅追加某个大附件时，协调者用已授权连接器按清单路径传输并校验，或者生成 `--full` 新包。不能把报告中的远程绝对路径当成本地链接。

## 自主选择最快可用通道

- 根据已有连接是否就绪、报告大小、近期成功传输的耗时/吞吐、启动开销和网络状况估计总耗时。优先复用连接，但不固定工具排名。小报告应考虑连接建立耗时，而非只比带宽。
- 没有可靠历史数据时可进行短小、低开销连通性或传输探测；不为测速反复传整份报告，不让测速时间超过实际收益。证据不足则记录“预计最快”，不能声称实测最快。
- 选择由协调 skill 执行，CLI 仅提供挂载复制和 rsync 拉取实现，不自动探测所有工具。可直接使用当前可用的其他文件传输工具；记录选择依据、实际耗时、文件大小与校验结果到本轮 delivery-decision.json。
- 首选通道失败时切换其他现有授权通道，保留远程原件。全部不可用才说明阻塞；不为加速新建公共下载链接、扩大权限或改用未经授权的第三方中转。

## 从本地通过 SSH 拉取

在**用户电脑**执行（不是服务器）：

```sh
python scripts/delivery.py pull EXISTING_SSH_ALIAS /absolute/bundle/path ABSOLUTE_LOCAL_DESTINATION
```

pull CLI 当前支持 POSIX 本地客户端，需要本地可用 rsync 和已配置 SSH 主机别名；使用已有认证和严格主机密钥检查，不提示密码、不关闭验证。脚本不配置 SSH。Windows 本机使用已有文件连接器或挂载目录，不直接运行 pull，不自动安装依赖。此 CLI 限制远程路径为 ASCII 字母、数字、`_ . / -`；其他路径用连接器或挂载方式。

默认只获取校验清单和报告，校验后立即放入本地目录并交付；仅明确选择完整包时再传附件；每文件有 300 秒超时，传输可从旁边的 `.任务名.arena-transfer` 缓存重试。协调者在后台运行较慢传输并持续报告进度，不等待长工具调用后才回应。delivery-progress.json 区分 report-ready 与 verified；receipt 仅在全部选定文件校验成功后写入。清单不能改写本地目录之外的路径。

交付时给出本地报告路径、远程原件位置、未同步附件数量及实际状态。只有本地写入且校验完成才称“已保存到本地”。没有真实远程传输测试时，明确区分单元测试与真实验证。

## 强制完成门槛：本地接收端验收

远程任务的状态必须依次为 `report-generated → transferring → local-verified`；无法完成时为 `delivery-blocked`。最终回复前逐项执行，不能因会话接续、工具返回成功或已有文件就省略：

1. 从可信客户端上下文和已确认配置确定用户电脑身份与本地目标路径；执行主机是服务器时，不能将其 hostname 或绝对路径当成客户端。主机名仅作检查字段，不是认证凭据；同名主机仍须以连接器/执行器所在端的可信上下文区分。
2. 记录本轮**最终版本**的源报告 SHA256、源路径与字节数，再按最快可用授权通道传输。报告内容有任何修改，旧回执立即失效，需重新传输与验收。
3. 在用户电脑的执行器运行下面命令；期望哈希必须来自步骤 2，不能仅从本地旧清单推导：

```sh
python scripts/delivery.py verify-local ABSOLUTE_LOCAL_TARGET SOURCE_REPORT_SHA256 CONFIRMED_CLIENT_HOST
```

该命令重新打开本地 report.html、核对实际接收主机和文件哈希，成功后写 `local-verification.json`（local-verified、主机、绝对路径、大小、哈希、核验时间）。失败返回非零并在目标目录可写时记录 failed，覆盖旧成功状态。`sync` 的 verified 仅说明传输目的目录文件匹配，不证明它是用户电脑。

4. 本地无法运行 Python 时，可用明确绑定用户电脑的现有文件工具完成同等的存在、可读、大小和 SHA256 检查，保存实际工具返回的证据与时间。不得由远端代理凭假设手写成功凭证。挂载写入成功后也要在本地接收端验收。
5. 协调者读取本次接收端验收输出，确认与步骤 2 的本轮报告哈希及用户电脑身份一致，再给出可点击的本地报告链接及“已本地校验”。将证据路径与交付状态记录到本轮 delivery-decision.json 和历史交付记录。
6. 验收失败时检查原因并尝试其他已授权可用通道；每个通道同一错误最多重试一次，随后切换，不无限循环。全部不可达或缺少本地执行能力时，明确写“报告已生成，本地交付未完成”，列出具体阻塞和远程保留位置，并只询问解除阻塞所必需的信息。不能用提醒用户自行下载最终报告替代已要求的自动本地交付。其他附件仍仅提示按需下载。

此规则约束协调流程，脚本提供可执行验收；无法跨越缺失权限或连接能力，不能保证不可达的电脑收到文件。未取得接收端证据时绝不宣称已送达。
