# 单文件阅读报告

远程交付按 [交付规则](delivery.md) 使用报告优先包：完整文字内嵌，大附件按需，原件使用包内相对下载链接。下述单文件规则适用于常规本地报告。

默认交付 report.html；report.md 保留为原件链接与评分的文字索引。HTML 离线可打开，CSS、交互脚本、正文与附件均嵌入，不依赖远程资源。普通引用仍跳转原网站。

## 页面顺序

1. 简短任务概述、完整任务折叠区、按 skill 名称跳转与全部展开／收起按钮。
2. 各候选完整结果。介绍只列项目来源、stars、项目简介、项目最新更新时间；查询日期作为小字。正文默认展开，二级章节可折叠，参考资料和附加文件默认收起。保持固定候选顺序，不按评分重排正文。
3. 所有方案之后展示评估表（名称、排名、状态、质量分、主要判断）；逐维证据、优缺点、适用场景及不确定性默认折叠。
4. 最后折叠展示调查、运行规则、实际模块和原始指令。会话中的优化／接续仍使用原生提问工具，HTML 按钮只控制阅读。

## 信息与呈现

- GitHub 项目更新时间采用 pushed_at，记录查询时间；无法核实时写“未获取”，不拿本轮快照时间代替。不适用与未获取区分。
- stars 优先精确值；若只看到网页简写，以 stars_display 保留“约 53.6k”等原展示精度，不用于替代选型打分的精确整数。工具包星数属于整个仓库，不属于某个模块。
- Markdown 基本标题、列表、表格与代码块直接呈现；复杂公式等暂保留源语法，不声称完整排版支持。图片内嵌，其他二进制附件内嵌下载；每项均提供原始字节下载。不可执行产物中的 HTML 或脚本。
- 同一候选的完整正文、来源和已登记附件必须全部收录，不能只保留摘要。跨文件内容不拼成新方案。
- 必要图示可由协调者补充到 presentation.json，注明是阅读示意及对应原稿章节，不能增添未经原稿支持的结论。原始产物与 judge.json 保持不变。
- 历史报告刷新前备份 report.html/report.md/ranking.json/interaction.json 到数据根 tmp 的独立子目录；刷新后核对原始产物哈希和评分。

## 可选 presentation.json

位于运行目录，由协调者准备，仅用于展示，不进入匿名评估包或选型分数。

```json
{
  "task_summary": "规划英文期刊论文",
  "candidates": {
    "variant-id": {
      "metadata": {
        "source": "https://github.com/owner/project",
        "repository": "owner/project",
        "description": "一句话说明项目用途。",
        "stars_status": "known",
        "stars": 120,
        "metadata_checked_at": "2026-10-22",
        "project_updated_at": "2026-10-20T10:00:00Z"
      },
      "diagrams": [{"title": "研究流程", "steps": ["文献", "假设", "验证"], "source": "answer.md 第 2 节"}]
    }
  }
}
```

未提供展示信息时读取 discovery.json 与 mapping.json；缺失字段显示未记录／未获取。页面首部不展示复杂选型信息，详细记录仍在末尾保留。
