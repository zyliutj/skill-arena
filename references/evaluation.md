# 评估规范

## 冻结标准

开始前制定约 4–7 个维度，权重总和 100。每维 0–5 分：0 缺失/不可用，1 重大缺陷，2 部分可用但需大修，3 基本满足有明确缺口，4 满足且证据充分，5 超出要求且增加实际价值。按任务为各维补充具体锚点；不能把文长、辞藻或 skill 遵循程度直接当作质量。

通用起点：需求契合 25、事实与证据 25、方法/逻辑 25、可执行性 15、表达与交付 10。任务不涉及外部事实时调整维度，在生成前写入 rubric.json。

英文期刊论文规划可用：问题和期刊契合 15、文献与研究缺口证据 25、方法和实验设计 25、资源可行性与风险 20、论文结构与英文表达 15。用户未给具体选题、材料或资源限制时，先获取这些关键信息；示例不等于实际论文任务。

涉及土木工程与强化学习文献时，遵循用户 AGENTS.md 的来源优先级，不能把优先误作仅限。核验代表性近邻工作、题名/作者/年份/DOI与论点支持关系；重点检查创新性主张。CCF 等级按适用官方目录核验。实验规划检查基线、公平预算、消融、多种子/不确定性、数据泄漏、约束满足与泛化验证；根据研究适用性判断，不机械要求所有项目。

## 证据和硬条件

每个分数附产物文件/段落定位、具体优点及缺陷；外部核验给来源和日期。区分已核验、无法访问、未核验和已证伪。无法访问不等于虚假；未核验的关键论断不能获“证据充分”。不得用不存在的实验结果或引用支持排序。

预先指定硬条件，例如未提交必要交付物、已证实伪造关键数据、违反用户核心范围。失败不与合格结果简单平均。status 使用 eligible / needs-review / disqualified / failed / blocked；只有 eligible 进入正式排序，needs-review 保留待审而不是默认为通过。

质量总分 = sum(weight × score / 5)，满分 100。默认分差不超过 3 分视作实用性并列区间；它是经验阈值，不是统计显著性结论。只运行一次不能给置信区间或宣称稳定优胜。

评估代理先逐项评分再做成对检查，反转匿名材料顺序重看最接近两项；这是同一评估者的偏差检查，不是第二份独立证据。结论冲突时降低置信度或并列，记录原因。大额决策或用户要求稳定性时提出同预算重复试验，不静默启动无限轮次。

## 结果格式

judge.json 使用如下结构。dimensions 名称必须与 rubric 完全一致，所有维度都需给分和证据。summary、strengths、weaknesses、best_for、uncertainty 必填非空文本。

```json
{
  "results": [{
    "id": "A",
    "status": "eligible",
    "dimensions": {"需求契合": {"score": 4, "evidence": "answer.md 第2段：满足…，缺少…"}},
    "summary": "总体判断",
    "strengths": "主要优点",
    "weaknesses": "主要缺陷",
    "best_for": "适用场景",
    "uncertainty": "尚未核验事项与影响"
  }]
}
```

失败项可用空 dimensions，但仍需以上说明字段。报告应另附核验日志与顺序检查记录。第三方评价只是线索，用户最终偏好单独记载，不改写原始评分。
